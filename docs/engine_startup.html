Start-up sequence

In order. Each one has a single thing to look at and a single thing that means it is wrong.

  1. Which computer is this session linked to?

    A Cowork session is bound to one machine at the moment you start it, and it can only ever see the folders that machine has shared. Right now that is six: 03 BIOLOGY (Public), ~/code, ~/code/answerable-skills, ~/deck_work, ~/Desktop, ~/Downloads.

    Wrong when a file you can see in Finder comes back "no such file" — it is outside those six, and the fix is to share the folder, not to restart anything.

  2. Is Claude Code pointed at the right place?

    Two separate settings go stale independently. The environment dropdown resets to Local every restart. And Claude Code only reads directories it was launched with or given since.

    /add-dir ~/code/answerable-skills
    Wrong when it says it cannot read a document. That is directory scope, never Full Disk Access — and it once meant Claude Code was signed into a different Google account's Drive than the session beside it.

  3. Which Google account is Chrome on?

    The live decks belong to the school account. Chrome has to be signed in as katherine.vonduyke@redclay.k12.de.us — check the avatar at the top right, or the /u/0/ in the address bar.

    Wrong when a deck opens View only. That is the wrong account, not a permissions failure, and no amount of requesting access fixes it.

  4. Is the Chrome extension actually holding?

    Click the Claude icon to the right of the address bar and leave its side panel open. The connection drops when the panel closes, and it drops silently.

    Wrong when one browser call works and the next says "extension is not connected." That is the panel closing, not the extension failing.

  5. Are you using the right browser for the job?

    Two browsers answer to Claude and only one of them is you. Chrome carries your school sign-in and can edit. The desktop app's built-in browser is a separate profile signed into nothing — it opens the decks read-only.

    Wrong when a deck opens View only and Chrome is on the right account: you are in the built-in browser, not Chrome.

Looked broken, wasn't

Every one of these cost real time before the actual cause turned up. None was a tool failing.

Claude Code could not read AT_docs on the Desktop
Directory scope. The Full Disk Access toggle had been on the whole time; the fix was /add-dir.
Claude Code insisted it was "in local"
The environment dropdown resets to Local on every restart. Nothing had broken.
Claude Code was reading the wrong Drive
It was signed into a different Google account than the session running beside it.
159 files on the Desktop were unreadable
iCloud had evicted them — present in Finder, zero blocks on disk. Fixed permanently with Keep Downloaded.
A file "still existed" after you deleted it
A stale mount cache on Claude's side. Your shell was right and Claude was wrong; when they disagree, the shell wins.
Git refused to commit — another process running
A leftover .git/index.lock from a call that died mid-write. Deleting the lock file is the whole fix.
Kept in answerable-skills. When a surface moves or an account retires, this is the file to change.
